## 1. Назначение работы

Создать приложение для планирования уборки, научиться работать с ветками GitHub, проверять изменения и выпускать готовую версию.

## 2. Файлы приложения

Приложение написано на HTML, CSS и JavaScript.

- `index.html` — страница и формы.
- `style.css` — оформление.
- `script.js` — работа кнопок, форм и списка дел.
- `model.js` — обработка дел и сохранение данных.
- `tests/` — проверки приложения и базы данных.
- `.gitignore` — список временных файлов.
- `.github/workflows/ci.yml` — автоматическая проверка.

Дела хранятся в браузере с помощью `localStorage`.

## 3. Работа с ветками

Основная ветка — **main**. Функции создавались в отдельных ветках:

- `feature/add-task-function` — добавление, изменение, удаление и сохранение дел. [PR #32](https://github.com/darazalilova-cpu/cleaning-planner-srs/pull/32).
- `feature/recurring-reminders` — повторения, история и напоминания. [PR #33](https://github.com/darazalilova-cpu/cleaning-planner-srs/pull/33).
- `feature/filters-and-ci` — фильтры и автоматическая проверка. [PR #34](https://github.com/darazalilova-cpu/cleaning-planner-srs/pull/34).
- `feature/database-3nf` — база данных. [PR #35](https://github.com/darazalilova-cpu/cleaning-planner-srs/pull/35).

Для объединения изменений создавались Pull Requests. Перед объединением проверялись изменения и оставлялись комментарии. PR #33 объединён через **Squash and merge** — его изменения сохранены одним коммитом.

[Посмотреть все Pull Requests](https://github.com/darazalilova-cpu/cleaning-planner-srs/pulls?q=is%3Apr+is%3Amerged)

## 4. Связь изменений с задачами

В описании Pull Request указывалось `Closes #номер`. После объединения GitHub закрывал соответствующие задачи.

Примеры:

- #11 — создание дела.
- #12 — изменение дела.
- #13 — удаление дела.
- #17 — повторяющиеся дела.
- #18 — выполнение и следующий срок.
- #21 — напоминания.

[Открыть задачи](https://github.com/darazalilova-cpu/cleaning-planner-srs/issues)

## 5. Автоматическая проверка

GitHub Actions запускается при изменениях в main и при создании Pull Request в main.

Проверяется:

- наличие файлов приложения;
- правильность записи JavaScript;
- создание и изменение дел;
- повторения, история и напоминания;
- сохранение данных;
- создание базы данных и её ограничения.

Выполняются 10 тестов JavaScript и 5 тестов SQLite.

[Посмотреть результаты проверок](https://github.com/darazalilova-cpu/cleaning-planner-srs/actions)

## 7. Проверка приложения

Проверены следующие действия:

- создание дела и запрет пустого названия;
- выбор комнаты, срока и повторения;
- изменение и удаление дела;
- отмена удаления;
- отметка о выполнении и появление следующего повторения;
- просмотр истории и фильтры;
- сохранение после перезагрузки;
- показ напоминания без повторного показа.

Чтобы открыть приложение, скачайте архив через **Code → Download ZIP**, распакуйте его и откройте `index.html` в браузере. Напоминания работают при открытом приложении.
